SortableJS 交互元素最佳实践

当列表项包含输入框、按钮和链接时，如何安全使用拖拽排序

示例 1：待办事项列表（推荐配置）

使用 handle 选项，只有拖动 handle 区域才能排序。 输入框、按钮和链接可以正常使用。

Sortable.create(todoList, { draggable: '.todo-item', handle: '.drag-handle', animation: 150 });

示例 2：无 Handle 配置（自动识别）

不使用 handle 选项时，SortableJS 会自动识别交互元素。 点击 input、textarea、button、select、a[href] 不会触发拖拽。

⚠️ 注意事项

  • 点击输入框、按钮、链接等交互元素不会触发拖拽
  • 点击列表项的空白区域或非交互元素（如普通 span）会触发拖拽
  • 如果需要更精确的控制，建议使用 handle 选项

推荐的最佳实践

✅ 推荐做法

  1. 使用 handle 选项 - 明确定义拖拽区域，避免与交互元素冲突
  2. 交互元素保持独立 - 输入框、按钮等放在 handle 之外，确保可点击
  3. 使用 delayOnTouchOnly - 在移动端减少误触，同时不影响桌面端体验
  4. 自定义 Web Components 使用 filter - 对于自定义组件，手动添加到 filter 选项

⚠️ 边界情况

自定义 Web Components：SortableJS 只会自动识别标准 HTML 交互元素（input、textarea、button、select、a[href]）。 如果你使用自定义组件（如 <my-input>、<v-btn> 等）， 需要手动将它们添加到 filter 选项中。

// 自定义组件需要手动配置 filter
Sortable.create(el, {
    filter: 'my-input, my-button, v-btn',
    preventOnFilter: false
});

配置选项说明

选项 说明 推荐场景
handle 指定拖拽触发区域 ✅ 列表项包含交互元素时强烈推荐
filter 指定不触发拖拽的元素 ⚠️ 自定义 Web Components 时需要
delayOnTouchOnly 仅在触摸设备启用延迟 ✅ 移动端减少误触
preventOnFilter filter 触发时是否阻止默认事件 ⚠️ 设为 false 允许交互元素正常行为
